# 安聆 VelaGuard 架构说明

> 与 `docs/prd/` 系列对应；本文只讲**已经实现的东西**长什么样，
> 每个模块都标注了对应的源码位置与 PRD 编号。

## 一、整体数据流

```text
                   ┌──────────────── 端侧（完全离线可用）─────────────────┐
板载麦克风 / wav ──►│ vg_capture      音频源抽象（MIC / WAV / 无源）       │
                   │      │ 16kHz 单声道，1 秒窗口，50% 重叠             │
                   │      ▼                                              │
                   │ vg_feature      预加重→Hamming→FFT→Mel→MFCC→40 维    │
                   │      │                                              │
                   │      ├─► vg_classifier  环境声景 int8 MLP  ─┐        │
                   │      ├─► vg_classifier  人声异常 int8 MLP  ─┤        │
                   │      └─► vg_enroll      个性化模板匹配     ─┤        │
                   │                                            ▼        │
                   │              SoundObservation / DistressObservation  │
                   │                            │                        │
                   │                            ▼                        │
                   │ vg_event_sm     三级风险状态机 + 五类规则 + 并发仲裁  │
                   │        │            + snooze + 夜间/时钟降级         │
                   │        ├──────────────► vg_event_log  100 条环形日志 │
                   │        ├──────────────► vg_ui         LCD 三页面     │
                   │        ├──────────────► vg_indicator  提示音 + LED   │
                   │        │                vg_input      按键/串口      │
                   │        ▼（仅"无人确认→紧急"时）                       │
                   │ vg_notifier ──► vg_agent（Skill 文案）               │
                   │        │                                            │
                   │ vg_uploader     幂等队列 + 断网补发                   │
                   └────────┼───────────────────────────────────────────┘
                            │ HTTP POST 结构化摘要（无音频、无对话文本）
                            ▼
                 prototype/console  Node 零依赖控制台 + SQLite
                            │ SSE
                            ▼
                 家属手机浏览器（局域网，零 App、零账号、零公网）
```

**依赖方向是单向的**：识别产生事件 → 状态机决定处置 → 硬件执行交互 →
日志保存结果 → 上传同步摘要。控制台、Agent、LLM 只消费摘要，
**不能反向接管端侧安全判断**。

## 三、状态机（PRD-03）

### 状态与等级

```text
                 观测命中
   正常监测 ──────────────► 可疑(SUSPECT)
                              │ 达到规则阈值
      ┌───────────────────────┼───────────────────────┐
      ▼                       ▼                       ▼
   提醒(NOTICE)           警告(WARNING)          紧急(EMERGENCY)
   只显示+轻提示          倒计时等待确认          持续提醒 + 远程通知
      │                       │                       │
      │              ┌────────┼────────┐              │
      │         已处理│    稍后提醒│  超时│             │已处理/误报
      │              ▼        ▼        ▼              ▼
      └──────────► 已关闭   挂起10分钟  无人响应 ──────► 已关闭
                            (最多2次)      │
                                           └──► 升级为紧急
```

事件轨道按 `eventType` 各一条，互不干扰；同时活跃时按
**等级 → 类别**排序展示（`distress_voice` ≥ `name_call_help` >
`alarm_beep` > `impact` > `water_flow`，人身安全优先于环境风险）。

### 五类规则（演示档阈值 / 正式档见 `config.example.json`）

| 事件 | 规则 | 实现 |
|---|---|---|
| `alarm_beep` | 高置信度连续 ≥ 5 秒且 ≥ 3 个窗口 → **直接紧急级** | `vg_rule_alarm_beep` |
| `water_flow` | 连续 30s → 提醒；120s → 警告；警告倒计时超时 → 紧急 | `vg_rule_water_flow` |
| `impact` | 单次高置信度 → 警告；**夜间**或 60s 内重复 2 次 → 紧急 | `vg_rule_impact` |
| `distress_voice` | 首次 → 警告（本地询问）；重复 ≥ 2 次或超时 → 紧急 | `vg_rule_distress` |
| `name_call_help` | **平静单次 → 只到提醒级且永不远程通知**；急促且重复 / 明确求救词 / 伴随异常人声 → 警告 → 紧急 | `vg_rule_name_call` |

「平静喊名字不报警」是靠 `local_only` 标记实现的：该标记为真时，
即使倒计时超时也只关闭事件、不触发 `on_escalate`，从源头杜绝
「听到名字就打扰家属」。

### 时钟降级（PRD-03）

板载 RTC 无备份电池。系统时间早于 2025-01-01 视为不可信，此时：

- 夜间加严规则**自动失效**，一律按日间标准执行；
- 事件带 `timeReliable:false`，LCD 与通知文案都显式提示"时间未同步"；
- 可选增强：光感持续低照度 ≥ 10 分钟可作为夜间旁证恢复加严规则
  （`vg_time_feed_lux`）。

## 四、识别引擎（PRD-01 / 07）

```
16kHz 单声道 1s 窗口（50% 重叠）
  → 预加重 0.97 → Hamming 25ms/10ms → 512 点 FFT
  → 26 路 Mel(20~7800Hz) → log → DCT → 13 维 MFCC
  → 均值(13) + 标准差(13) + 一阶差分均值(13) + 过零率(1) = 40 维
  → 两层 MLP（int8 权重 + float 偏置 + ReLU + Softmax）
```

三条通道共享同一个窗口的同一份特征，只算一次：

1. **环境声景**：4 分类（other / alarm_beep / water_flow / impact）
2. **人声异常**：4 分类（none / moan / scream / shout_help）
3. **个性化模板**：归一化欧氏距离匹配，命中给出 `matchedPhrase` /
   `personLabel` / `urgency`

静音窗口（能量 < -55 dBFS）直接跳过推理，省电且天然抑制底噪误报。

**为什么是 MLP 不是 DS-CNN**：PRD-07 的降级决断表规定「板端量化推理示例
2 个工作日内跑不通 → 降级 MFCC + 小型分类器，权重导出 C 数组，不引入新
推理框架」。当前工程内没有可直接在 Gemini-S1 上跑的量化推理示例，
开发板也未到手，因此直接落地降级路线。接口保持不变，后续换 DS-CNN
只需替换 `vg_classifier.c` 的前向实现。

## 五、可靠性设计

| 失效场景 | 行为 |
|---|---|
| 无麦克风 / 音频源不可用 | 自动转入模拟注入模式，其余链路照常 |
| 无 LED / 扬声器 / 按键 | 降级为控制台指示，串口命令等价操作 |
| `/data` 不可写 | 事件日志降级为纯内存，本地告警不受影响 |
| 控制台不可达 | 事件入队落盘，网络恢复后按 `eventId` 幂等补发 |
| ai_agent / LLM 失败 | 三级回退到 Skill 规则表 → 端侧内置模板，**通知不丢** |
| 时间不可信 | 夜间加严规则降级，不产生误升级 |
| 断电重启 | 事件日志、模板、待发送队列全部从 `/data` 恢复 |

### 两个 NuttX 特有的坑（已修复，值得记录）

1. **文件描述符属于任务，静态变量却跨任务**：FLAT 构建下每条 NSH 命令
   都是新任务，但 `.data`/`.bss` 是全局共享的。最初事件日志持有长期
   打开的 fd，第二条 `velaguard` 命令里这个 fd 已经非法，触发
   `lib_fdcheck.c` 断言 panic。现改为所有落盘操作按需 open/close。
2. **跨命令的状态必须保留**：修复上一条时一度改成"换任务就重新初始化"，
   结果把状态机轨道也清空了，`velaguard sim` 之后 `velaguard ack` 找不到
   事件。现在区分**进程私有资源**（fd，换任务重开）与**共享状态**
   （事件轨道，换任务只换回调不清空），见 `vg_sm_set_callbacks()`。

## 六、隐私边界的落点

隐私不是靠"我们保证"，而是靠代码里三处硬约束：

1. **端侧**：`vg_safety_event_t` 结构体里根本没有音频或文本字段，
   音频只在 `vg_capture` 的固定大小缓冲里流过，不落盘、不出结构体。
2. **Skill**：`SKILL.md` 明确规定输入只有结构化字段，并要求模型
   不得索取音频或对话内容。
3. **控制台**：`server.js` 的 `FORBIDDEN_FIELDS` 黑名单直接 400 拒绝
   带 `audio` / `pcm` / `wav` / `transcript` / `rawText` / `dialog`
   的负载并打日志——即使端侧被改坏，控制台这一关也拦得住。

`tests/run_tests.sh` 第 5、6 节把上述第 3 条和"仓库内无音频文件、
无明文凭证"做成了自动化断言。

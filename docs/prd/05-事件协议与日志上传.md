# PRD-05 事件协议与日志上传(event_log / uploader / prototype/console)

## 目标

定义端侧、模拟脚本、Agent 与控制台共用的结构化事件协议;本地限长保存事件记录;网络可用时上传摘要并支持重试。

> 协议与控制台属于**模拟器线**,是板前最先落地的模块;控制台同时承担远程通知与演示界面职责(PRD-06)。

## 结构化事件协议

### eventType 枚举

| `eventType` | 含义 |
|---|---|
| `alarm_beep` | 烟雾或燃气报警器蜂鸣 |
| `water_flow` | 持续水流或疑似漏水 |
| `impact` | 玻璃破碎、重物撞击或异常摔倒类冲击 |
| `distress_voice` | 呻吟、痛苦叫声、哭喊或连续呼救 |
| `name_call_help` | 姓名、亲属称呼、方言短语或明确求救词 |

### 字段枚举

- `level`:`notice` / `warning` / `emergency`
- `localStatus`:`pending` / `handled` / `false_alarm` / `snoozed` / `no_response`
- `uploadReason`:`manual_test` / `escalated` / `sync`

### SafetyEvent 字段

事件 ID、设备 ID、类别、等级、综合置信度、开始时间、持续时间、本地处理状态、上传原因、摘要。人声事件可附带 `matchedPhrase`、`personLabel`、`urgency`、`repeatCount`;**禁止**附带对话文本或原始音频。时间戳依赖 NTP 同步,时间不可信时以 `timeReliable: false` 标记(见 PRD-03)。

```json
{
  "eventId": "evt_001",
  "deviceId": "velaguard_demo_001",
  "eventType": "name_call_help",
  "level": "warning",
  "confidence": 0.86,
  "startedAt": "2026-07-05T22:40:00+08:00",
  "durationSec": 8,
  "localStatus": "no_response",
  "uploadReason": "escalated",
  "matchedPhrase": "快来人",
  "personLabel": "家庭成员 A",
  "repeatCount": 3,
  "summary": "夜间检测到急促求助呼喊，用户未确认"
}
```

## 本地事件日志(event_log)

- 限长追加,最多 **100 条**,写满后环形覆盖最旧记录。
- 记录完整状态流转,支持历史记录页(PRD-04)查询。

## 存储与可靠性

- 事件日志、个性化模板、配置文件统一存 `/data` 分区(具体文件系统以官方分区表为准);关键记录写入即 flush,断电重启后不丢失。
- 板载主存储为 **16MB SPI NOR + TF 卡槽**:固件与模型的闪存预算见 PRD-07;开发期受控采样数据只写 TF 卡,不进主存储、不进 Git。

## 上传通道(uploader)

- HTTP POST 结构化摘要到控制台(局域网地址,配置见 PRD-06);仅上传结构化摘要。
- 网络中断不影响本地提醒;未发送通知标记为待发送,恢复后自动重试补发(按 `eventId` 幂等)。

## 通知与演示控制台(prototype/console)

Node.js/Express + SQLite,部署在演示用笔记本或手机热点局域网内,双重角色:

1. **板前联调**:验证协议、模拟五类事件、检查状态流转;
2. **家属通知端与演示界面**(PRD-06):SSE 实时推送事件卡片到手机浏览器。

接口:

- `POST /events`:上传事件摘要;
- `GET /events`:查询事件列表和详情;
- `PATCH /events/:id`:标记已处理、误报或稍后提醒;
- `GET /stream`:SSE 实时事件流(通知推送用)。

控制台不承担端侧安全判断,不构成自建公网云服务;与 Skill 通知模板共用同一份事件协议。配套 `prototype/simulate/` 脚本可按序注入五类模拟事件。

## 验收

- 不用真实硬件,用模拟事件即可跑通"事件产生 → 本地状态 → 结构化摘要 → Agent 文案 → 通知/记录"闭环。
- 日志写满 100 条后正确覆盖;断电重启后记录不丢失。
- 断网期间事件入队,恢复后补发成功且无重复(幂等)。

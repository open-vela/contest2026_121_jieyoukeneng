# PRD-03 事件状态机与告警规则(event_state_machine)

## 目标

用可解释规则状态机把识别层的观测结果转化为三级安全事件,结合置信度、持续时间、重复次数、时段和用户确认状态决定提醒、升级与通知,避免单次声音直接触发高等级告警。

> 本模块属于**模拟器线**:不依赖硬件,用模拟观测输入即可完整开发与测试。

## 告警三级

| 等级 | `level` | 行为 |
|---|---|---|
| 提醒级 | `notice` | 只显示状态并轻提示,不远程通知 |
| 警告级 | `warning` | 需本地确认,LCD + 提示音 + LED 进入倒计时提醒 |
| 紧急级 | `emergency` | 持续本地提醒,上传结构化摘要并触发远程通知(PRD-06) |

## 状态集合

正常监测、可疑、提醒、警告、紧急、已处理(`handled`)、误报(`false_alarm`)、稍后提醒(`snoozed`)、无人响应(`no_response`)。

## 五类事件规则(演示初始阈值,实机可调)

| 事件 | 规则 |
|---|---|
| `alarm_beep` | 高置信度连续约 5 秒(多个连续窗口确认)→ 直接紧急级 |
| `water_flow` | 连续命中 30s → 提醒级;120s → 警告级;警告级 60s 无人确认 → 紧急级。正式阈值 3 分钟,演示构建用缩短阈值 |
| `impact` | 单次高置信度瞬态 → 警告级;夜间或 60s 内重复 2 次 → 紧急级 |
| `distress_voice` | 先触发"是否需要帮助"本地确认;重复命中或无人响应 → 升级 |
| `name_call_help` | 平静单次呼喊 → 仅本地确认;急促重复呼喊、明确求救词、或与异常人声组合 → 升级 |

- 用户确认"已处理"或"误报"后停止升级;"误报"记录反馈但 V1 不在线学习。

## 时钟与夜间判定

- 默认夜间时段:22:00 — 次日 07:00。
- 联网时通过 NTP 同步系统时间;板载 RTC 无备份电池,**断电重启后时间不可信**。
- 时间不可信(未同步过 NTP)时,夜间加严规则自动失效,一律按日间标准执行,避免时钟漂移造成误升级;LCD 显示"时间未同步"。
- 可选增强:利用板载 LTR-553 光感,持续低照度 ≥ 10 分钟作为"夜间"旁证,在时间不可信时恢复夜间加严规则。

## 稍后提醒(snoozed)语义

- 用户选择"稍后提醒"后,事件挂起 **10 分钟**,到期重新进入警告级倒计时。
- 同一事件最多 snooze **2 次**;第三次到期仍未确认,按 `no_response` 处理并升级。

## 多事件并发仲裁

- 多个事件同时活跃时,LCD 与本地提醒展示**优先级最高**的事件;其余事件各自独立计时与流转,不丢弃、不合并。
- 优先级:先按等级(`emergency` > `warning` > `notice`);同级按类别:`distress_voice` ≥ `name_call_help` > `alarm_beep` > `impact` > `water_flow`(人身安全 > 环境风险)。
- 远程通知按事件独立发送,控制台按事件分条展示;高优先事件确认后自动切换到下一个待处理事件。

## 交互与超时

- 警告级进入倒计时;超时无人确认 → `no_response` → 紧急级 → 触发 PRD-06 通知链路。
- 每次状态流转写入本地事件日志(PRD-05),全程可追踪。

## 验收

- 五类核心声音均能按规则进入正确等级。
- 普通姓名呼喊不会直接产生远程紧急通知。
- 用户确认后不再升级;snooze 两次后第三次超时正确升级;事件状态在日志中完整可追踪。
- 并发场景:同时注入水流 + 呼救,呼救优先展示,两事件独立完成各自流转。
- 时间未同步场景:重启后(未联网)夜间加严规则不生效,无误升级。
- 支持按钮、串口命令或脚本注入五类模拟事件,走完全相同的状态机(演示兜底,见 PRD-08)。

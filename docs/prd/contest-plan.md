## 一、项目定位、目标硬件与 V1 边界

**项目名称:** 安聆 VelaGuard:无摄像头家庭异常声景 AI Agent。

**一句话定位:** 面向独居长辈家庭看护场景,设备在本地识别异常声音和求助人声,先提醒用户,无人确认后升级为家属侧远程通知。

**目标开发板:** 全志润芯微 Gemini-S1 R528(openvela/NuttX,`dev-ai-contest-2026` 分支)。该板已适配 openvela,具备 Cortex-A7、LCD、音频输入输出、板载按键、Wi-Fi/BLE 等能力,覆盖端侧采集、识别、显示、提醒和联网闭环。

**硬件 fallback:** openvela 模拟器。比赛评审接受"模拟器或硬件"运行,开发全程双线并行(见"三、实施阶段"),开发板能否到手、何时到手不阻塞核心交付。

端侧业务优先使用 openvela/NuttX 原生应用实现。比赛交付不依赖摄像头、原始录音上传或公网云服务;局域网控制台只承担通知/演示端和协议联调职责,不承担端侧安全判断。

### V1 目标(提交前完成的可演示原型)

- 端侧持续采集音频,不上传或长期保存原始录音。
- 真实识别五类核心安全声景(下表),另设背景噪声和普通说话负样本。
- 支持家庭成员主动录入姓名、昵称、亲属称呼和常用求救表达,覆盖比赛演示所选方言。
- 结合置信度、持续时间和重复次数生成提醒、警告、紧急三级事件。
- LCD/扬声器提示音/RGB LED 本地提醒,支持"已处理""误报""稍后提醒"确认。
- 无人确认时调用自定义 `anling-home-safety` Skill,实时推送到家属手机浏览器(局域网控制台)。
- 本地保存最近 100 条结构化事件记录。
- 提供完整代码、模型、数据来源、AI Coding 日志、演示视频和隐私说明。

| # | 声景 | eventType | 开发顺序 |
|---|---|---|---|
| 1 | 烟雾/燃气报警蜂鸣 | `alarm_beep` | 1 |
| 2 | 呻吟/痛苦叫声/哭喊/连续呼救 | `distress_voice` | 2 |
| 3 | 持续水流/疑似漏水 | `water_flow` | 3 |
| 4 | 姓名/亲属称呼/方言求救词 | `name_call_help` | 4 |
| 5 | 玻璃破碎/重物撞击 | `impact` | 5 |

**V1 不包含:** 自制 PCB、手机原生 App(家属侧用浏览器页面)、自建公网云服务、在线学习、HiFi4 DSP 优化、完整语音转写、全方言覆盖、多传感器融合。

> 注:Gemini-S1 板载已有 SHTC3 温湿度与 LTR-553 光感传感器。V1 仅允许用光感辅助夜间判定(PRD-03 可选项),不做其他传感器融合。

### 核心能力:人声求助与方言适配(纳入 V1 开发、演示和验收)

- 识别"呼喊指定姓名""救命""快来人"等求助表达,以及呻吟、痛苦叫声、哭喊、连续呼救等非语言人声事件;结合持续时间、重复次数和环境上下文判断风险。
- 采用"通用人声异常检测 + 用户个性化短语/声音样本"两阶段方案;支持普通话和比赛演示所选方言,不承诺覆盖所有方言或完整语音转写。
- **升级语义:** 单独、平静地呼喊姓名只触发本地"是否需要帮助"确认;急促重复呼喊、明确求救词,或呼喊伴随呻吟时才升级为远程通知。
- 录入必须由用户主动开启、明确告知用途;显示名称从预设标签选择或自动编号(板端无键盘);模板仅存本地,可随时查看、重录、删除。
- 默认不保存或上传完整家庭对话;检测到疑似求助事件后,只将结构化摘要交给 Agent。
- 验收覆盖不同家庭成员、不同距离、背景电视声以及普通话/方言混合条件下的召回率与误报率。

### 隐私红线(所有模块共同遵守)

1. 原始录音不上传、不长期保存;仅允许内存环形缓冲与开发阶段受控采样(采样数据写 TF 卡,不进主存储、不进 Git)。
2. Agent 与任何远程端只接收结构化事件摘要,不得接收原始音频或完整对话文本。
3. 个性化录入必须用户主动开启,只保存声学特征/模板,支持随时查看、重录、删除。
4. Git 历史、日志、远程通知中不得出现原始家庭录音与明文密钥/凭证。

## 二、系统设计

```text
板载麦克风
    ↓ 48kHz 采集 → 重采样 16kHz/单声道/1s 滑动窗口(50% 重叠)
    ├── 环境声景分类:报警/水流/破碎撞击(PRD-01)
    ├── 非语言人声异常检测:呻吟/痛苦叫声/哭喊(PRD-01)
    └── 本地关键词与个性化模板:姓名/称呼/求救词/方言(PRD-02)
               ↓ SoundObservation / DistressObservation
事件融合与风险状态机(PRD-03) ────→ 本地事件日志(PRD-05)
    ├── LCD/扬声器提示音/RGB LED 本地提醒与确认(PRD-04)
    └── 超时未确认 → anling-home-safety Skill(PRD-06)
                        ↓ 结构化摘要 + 通知文案
              局域网演示控制台 → 家属手机浏览器实时推送
              (可选扩展:webhook 转发飞书/钉钉/ntfy 等)
```

依赖方向:**识别产生事件 → 状态机决定处置 → 硬件执行交互 → 日志保存结果 → 上传同步摘要**。端侧核心链路必须可完全离线运行;控制台、Agent 和通知只消费摘要,不能反向接管端侧安全判断。

核心接口(定义详见 PRD-01/05):

- `SoundObservation`:时间、声音类别、置信度、窗口长度。
- `DistressObservation`:人声事件类型、匹配短语或人员标识、置信度、急促程度、重复次数;不含对话文本或原始音频。
- `SafetyEvent`:事件 ID、类别、等级、置信度、起止与持续时间、本地处理状态、上传原因、时间可信标记(`timeReliable`)。
- Agent 只接收结构化事件;本地日志限长 100 条环形覆盖;Skill 部署于 `/data/agent/skills/anling-home-safety/`。

### 告警等级与五类事件规则(详见 PRD-03)

端侧采用"轻量识别模型 + 可解释规则状态机":模型只判断类别和置信度,处置由规则决定。

- **提醒级 `notice`**:只显示状态并轻提示,不远程通知。
- **警告级 `warning`**:需本地确认,LCD + 提示音 + LED 进入倒计时。
- **紧急级 `emergency`**:持续本地提醒,上传摘要并触发远程通知。

演示初始阈值(实机可调):报警蜂鸣高置信度连续约 5 秒直接紧急级;水流 30s 提醒、120s 警告、警告 60s 无确认转紧急(正式阈值 3 分钟,演示构建缩短);破碎/撞击单次高置信度警告,夜间或 60s 内重复 2 次紧急;呻吟/求救词先本地确认,重复或无响应升级;姓名平静单次仅本地确认,急促重复或组合异常人声才升级。

- **时钟与夜间判定:** 默认夜间 22:00—07:00;联网 NTP 同步,断电重启后时间不可信时夜间加严规则自动失效(按日间标准),可选用光感低照度作旁证。
- **稍后提醒:** snooze 挂起 10 分钟,同一事件最多 2 次,第三次超时按无人响应升级。
- **并发仲裁:** 多事件同时活跃时按等级、再按"人身 > 环境"类别优先展示,各事件独立计时流转,通知分条发送。
- 用户"误报"后记录反馈,V1 不在线学习。

### 本地交互与硬件(详见 PRD-04;按原理图修正:板上无独立蜂鸣器)

- LCD 只做三个页面:监测首页(含录入入口、Wi-Fi/时间同步状态)、事件确认页、历史记录页。
- 确认操作:已处理、误报、稍后提醒。
- 提醒通道:扬声器播放分级提示音 + 板载 WS2812 RGB LED 状态色(守护绿/警告黄/紧急红)+ LCD 背光唤醒。
- 输入:板载 LRADC 按键(约 5 键)为主;电容触摸为非依赖增强;串口命令作开发/演示注入。
- **录放并发约束:** 提示音播放与守护采集的全双工能力须在实机基线第一周验证;不支持则时分方案(提示音期间暂停采集 ≤ 2s)。
- **音频通路互斥:** 守护采集与 ai_agent PTT 对话、录入模式互斥,切换时 UI 明示"守护已暂停",退出自动恢复。
- 板级原则:优先使用官方 Gemini-S1 板级配置(`nsh_minidisplay`)启用外设,不修改 `vendor/` 上游代码。

### 结构化事件协议(详见 PRD-05)

端侧、模拟脚本、Agent 和控制台统一使用五类 `eventType`(见 V1 边界表);字段枚举:`level` = `notice`/`warning`/`emergency`;`localStatus` = `pending`/`handled`/`false_alarm`/`snoozed`/`no_response`;`uploadReason` = `manual_test`/`escalated`/`sync`。人声事件可附带 `matchedPhrase`、`personLabel`、`urgency`、`repeatCount`,不附带对话文本或原始音频。示例:

```json
{
  "eventId": "evt_001",
  "deviceId": "velaguard_demo_001",
  "eventType": "name_call_help",
  "level": "warning",
  "confidence": 0.86,
  "startedAt": "2026-07-05T22:40:00+08:00",
  "durationSec": 8,
  "localStatus": "no_response",
  "uploadReason": "escalated",
  "matchedPhrase": "快来人",
  "personLabel": "家庭成员 A",
  "repeatCount": 3,
  "summary": "夜间检测到急促求助呼喊，用户未确认"
}
```

存储:事件日志、模板、配置统一存 `/data` 分区,关键记录写入即落盘;主存储为 16MB SPI NOR + TF 卡槽,开发采样只写 TF 卡。

### 模型策略(详见 PRD-01/07)

- 输入统一 16kHz 单声道、约 1 秒窗口、50% 重叠;log-mel 或 MFCC 特征;数据按录音来源分组切分。
- 环境声音用多分类模型(int8 轻量 DS-CNN 优先);呻吟等用独立人声异常检测模型;姓名和方言求救词用本地关键词检测或声学模板匹配。
- 姓名数据必须同时包含平静负样本和急促正样本,避免"听到名字就报警"。
- 资源预算:两个 int8 模型合计 ≤ 1MB,关键词/模板 ≤ 200KB,闪存总增量 ≤ 2MB;识别链路常驻内存 ≤ 8MB(实机标定修订);单窗口处理 < 500ms(Cortex-A7,不依赖 HiFi4)。
- 降级决断(阶段相对):板端量化推理示例接入 2 个工作日未跑通 → 降级 MFCC + 小型分类器(权重导出 C 数组);端侧识别阶段过半 CNN 仍不稳定 → 强制小分类器;通用关键词模型不稳定 → 保底个性化模板方案(2 姓名 + 3 求救短语 + 1 方言)。
- 开发顺序固定:烟雾报警声 → 呻吟/明确求救词 → 持续水流声 → 姓名与方言个性化录入 → 破碎/撞击声。

### 通知与演示控制台(详见 PRD-05/06)

`prototype/console` 双重角色:板前协议联调 + 家属通知端。接口:`POST /events`、`GET /events`、`PATCH /events/:id`、`GET /stream`(SSE)。

通知通道分级:**主通道(V1 验收)** = 局域网控制台 SSE 推送到家属手机浏览器,通知卡片含事件类型、时间、持续时间、置信度和 Agent 建议动作——演示现场手机热点组网即可,零公网依赖、零账号审批、零 App 安装;**可选扩展(非验收)** = webhook 转发飞书/钉钉/企业微信/ntfy。LLM 不可用时用本地模板文案兜底发送;断网按 `eventId` 幂等补发。

## 四、测试与最终验收

### 测试要求

- 每类核心声音 ≥ 20 次实机触发测试,**触发成功率 ≥ 80%**。
- ≥ 30 分钟家庭噪声误报测试(电视、音乐、交谈、平静喊名、做饭);高风险误报 ≤ 1 次/30 分钟。
- ≥ 2 名说话者 × 近/远距离 × 普通话/方言 × 电视背景声的求救词与姓名识别矩阵。
- 异常场景:断网、重启、控制台不可用、日志写满、LLM 请求失败——本地能力必须继续工作。
- 时钟场景:重启未联网时夜间规则正确降级;NTP 恢复后时间戳正确。
- 音频通路场景:对话/录入与守护互斥切换正确,退出自动恢复。

### 最终验收场景(10 项)

1. 烟雾报警声 → 识别并本地提醒 → 无人确认 → 家属手机浏览器收到紧急推送。
2. 持续水流 → 短时只记录 → 超阈值升级 → "已处理"后停止通知。
3. 破碎/撞击 → 瞬态风险事件 → 要求确认。
4. 呻吟/求救词 → 主动询问是否需要帮助 → 无响应/重复出现 → 远程推送。
5. 录入姓名/称呼/方言短语后,急促重复呼喊触发确认与升级;平静单次不远程通知。
6. "误报"记录反馈且不再升级;"稍后提醒"两次后第三次超时正确升级。
7. 断网仍可识别与本地提醒;恢复后补发通知且不重复。
8. 控制台/Agent/LLM 全不可用 → 端侧安全能力仍工作。
9. 并发注入水流 + 呼救 → 呼救优先展示,两事件独立流转。
10. 全链路(控制台、Git 仓库、事件日志)无原始家庭录音与明文密钥。

### 演示视频(官方限 ≤ 5 分钟)

主线按 3 分钟设计,预留时间给复现说明与 AI Coding 使用亮点:问题引入 → 设备亮相 → 烟雾报警 → 持续水流升级 → 破碎撞击确认 → 呻吟/求救词询问与升级 → 个性化录入与急促呼喊 → **家属手机浏览器实时收到推送卡片** → 历史记录 → 隐私边界收尾。真实模型不稳定时,用按键/串口/脚本触发相同状态机;演示重点是端侧优先、主动处置和隐私边界。

## 五、明确假设与风险控制

- Gemini-S1 官方音频补丁和 `nsh_minidisplay` 配置作为实机基线,不自行重写媒体框架。
- V1 推理运行在 Cortex-A7,不把 HiFi4 DSP 部署作为交付前提。
- 五类核心声音均纳入 V1;时间紧张时减少扩展样本和 UI 美化,不删除呻吟、求救词或姓名呼喊能力。
- 方言边界是支持用户录入并识别比赛所选方言短语,不承诺覆盖所有方言或完整转写。
- 所有降级决断按阶段相对条件执行(见 PRD-07/08),不因等待日历节点拖延。
- 所有技术变更只放专属仓对应子目录;上游参考路径的工作区改动不混入提交。

| 风险 | 应对 |
|---|---|
| 开发板不能确认获取/到手晚 | 模拟器线独立成立:状态机 + UI + Skill + 通知闭环在模拟器完成并可演示 |
| 板端算力不足 | int8 轻量模型;失败降级 MFCC + 小型分类器/模板匹配 |
| 录放不支持全双工 | 时分方案:提示音期间暂停采集 ≤ 2s |
| 麦克风与 ai_agent PTT 冲突 | 互斥模式切换,UI 明示"守护已暂停",退出自动恢复 |
| 平静喊姓名误报 | 平静负样本 + 急促正样本 + 重复次数规则;单次平静呼喊只本地确认 |
| 录入内容泄露 | 主动授权、可查看/重录/删除;只存模板不存录音 |
| 时钟不可信导致误判 | NTP 同步 + 夜间规则降级 + 可选光感旁证 |
| 网络/Agent/控制台不可用 | 本地闭环不依赖网络;LLM 失败用模板文案;恢复后幂等补发 |
| 演示现场网络受限 | 手机热点组网 + 局域网控制台,零公网依赖;模拟注入兜底 |
| 时间紧张 | 减少扩展样本与 UI 美化;不删除五类核心能力 |

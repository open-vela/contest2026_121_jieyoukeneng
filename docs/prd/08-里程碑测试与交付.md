## 测试要求(阶段 F)

- 每类核心声音 ≥ 20 次实机触发测试,**触发成功率 ≥ 80%**。
- ≥ 30 分钟家庭噪声误报测试(电视、音乐、交谈、平静喊名、做饭);高风险误报 ≤ 1 次/30 分钟。
- ≥ 2 名说话者 × 近/远距离 × 普通话/方言 × 电视背景声的求救词与姓名识别矩阵。
- 异常场景:断网、重启、控制台不可用、日志写满、LLM 请求失败——本地能力必须继续工作。
- 时钟场景:断电重启未联网时,夜间加严规则正确降级,无误升级;NTP 恢复后时间戳正确。
- 音频通路场景:ai_agent 对话/录入模式与守护采集互斥切换正确,退出后守护自动恢复。

## 最终验收场景(10 项)

1. 播放烟雾报警声 → 识别并本地提醒 → 无人确认 → 家属手机浏览器收到紧急推送。
2. 持续水流 → 短时只记录 → 超阈值升级 → "已处理"后停止通知。
3. 破碎/撞击 → 瞬态风险事件 → 要求确认。
4. 呻吟/求救词 → 主动询问是否需要帮助 → 无响应/重复出现 → 远程推送。
5. 录入姓名/称呼/方言短语 → 急促重复呼喊触发确认与升级;平静单次不远程通知。
6. "误报"确认 → 记录反馈且不再升级;"稍后提醒"两次后第三次超时正确升级。
7. 断网仍可识别与本地提醒;恢复后补发通知且不重复。
8. 控制台/Agent/LLM 全不可用 → 端侧安全能力仍工作。
9. 并发注入水流 + 呼救 → 呼救优先展示,两事件独立流转。
10. 全链路(控制台、Git 仓库、事件日志)无原始家庭录音与明文密钥。

## 演示视频(官方限 ≤ 5 分钟)

主线按 3 分钟设计,预留时间给复现说明与 AI Coding 使用亮点:

问题引入 → 设备亮相(LCD 守护状态)→ 烟雾报警 → 持续水流升级 → 破碎撞击确认 → 呻吟/求救词询问与升级 → 个性化录入与急促呼喊 → **家属手机浏览器实时收到推送卡片** → 历史记录 → 隐私边界收尾(原始音频不出设备)。

真实模型不稳定时,用按键/串口/脚本触发相同状态机;演示重点是端侧优先、主动处置与隐私边界。

# PRD-06 Agent Skill 与远程通知(anling-home-safety)

## 目标

无人确认的事件由自定义 ai_agent Skill 生成通知文案,经通知通道送达家属侧,完成"本地提醒 → 超时升级 → 远程通知"闭环。**通知方案以演示便利和零外部依赖为第一优先级,不绑定飞书。**

## 通知通道设计(抽象接口 + 分级实现)

端侧实现统一的 notifier 接口(输入 = 结构化事件 + Agent 文案),通道可配置:

### 主通道(V1 验收项):局域网演示控制台推送

- 板端 POST 事件到 `prototype/console`(PRD-05),控制台经 **SSE** 实时推送到家属手机/笔记本**浏览器页面**,弹出通知卡片并播放提示音。
- 演示现场只需一部手机开热点组网(板子 + 控制台 + 观看设备),**零公网依赖、零账号审批、零 App 安装**,评委扫码或投屏即可看到"家属视角"。
- 控制台页面提供"家属视角"全屏模式:实时通知卡片 + 历史事件列表。

### 可选扩展(非验收项):Webhook 适配器

- 同一份文案可配置转发到任意 IM 自定义机器人(飞书/钉钉/企业微信)或 ntfy 类推送服务;仅在网络与账号条件允许时启用,失败不影响主通道。

### 板端备选展示

- ai_agent 的 `ask` 对话能力保留,用于演示"设备端 AI 问答/建议"场景。

## Skill 设计

- 名称:`anling-home-safety`,部署路径 `/data/agent/skills/anling-home-safety/`。
- 输入:**仅结构化事件**——事件类型、时间、持续时间、置信度、用户是否响应;不得接收原始音频或对话文本。
- 职责:根据风险等级生成简洁通知文案与建议处理方式(如"检测到疑似求助呼喊,建议立即电话确认"),继续本地提醒,并调用 notifier 发送。

## 通知内容

通知卡片包含:事件类型、发生时间(含时间可信标记)、持续时间、置信度、Agent 建议动作。与控制台共用同一份事件协议(PRD-05)。

## 配置与凭证管理

- Wi-Fi SSID/密码、控制台地址、可选 webhook 地址等统一存 `/data/velaguard/config.json`,**不进 Git**;仓库只提供 `config.example.json` 模板与 README 配置说明。
- 演示前通过串口/nsh 写入实际配置;提交前核查 Git 历史无任何真实凭证。

## 触发条件

- 本地警告级倒计时超时无人确认(`no_response`)→ 升级为紧急级 → 发送远程通知。
- 用户及时确认"已处理"或"误报" → **不发送**升级通知。

## 可靠性要求

- 网络中断不影响本地提醒;通知标记待发送,网络恢复后按 `eventId` 幂等重试。
- Agent、LLM 或控制台不可用时,本地分类、提醒和事件记录必须继续工作;LLM 不可用时 notifier 使用**本地模板文案**兜底发送(不因 Agent 失败丢通知)。

## 板端基线(依赖官方能力)

- ai_agent 联网与 MiMo 配置,首次 `ask` 对话跑通(命令以板端 `help` 为准:优先 `router_set mimo`,旧版本按 README 用 `set_llm`)。

## 验收

- 事件无人响应后,家属手机浏览器 **3 秒内**收到推送卡片;用户及时处理时不推送。
- 断网期间升级的事件,恢复后补发成功且不重复。
- LLM 请求失败时,模板文案通知仍正常送达。
- 控制台/Agent 全部不可用时,端侧本地提醒、确认、日志闭环仍完整可演示。

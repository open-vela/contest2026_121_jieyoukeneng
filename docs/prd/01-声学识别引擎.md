# PRD-01 声学识别引擎(audio_detector)

## 目标

在 Gemini-S1 端侧持续采集音频,实时识别环境异常声与非语言人声异常,输出结构化观测结果给状态机;不保存、不上传原始录音。

> 本模块属于**实机线**:识别算法先在电脑端验证(PRD-07),板到手后再接入;openvela 模拟器不承担音频采集验证。

## 输入与预处理

- 板载麦克风 48kHz 采集,基于官方 media server 录音路径。
- 统一重采样为 **16kHz 单声道**,约 **1 秒窗口、50% 重叠** 的滑动窗口。
- 特征:log-mel 或 MFCC。
- 仅允许内存环形缓冲;禁止写入完整原始录音(开发阶段受控采样写 TF 卡除外)。

## 音频通路占用约束

- 守护采集**独占麦克风**,与 ai_agent PTT 语音对话、录入模式(PRD-02)互斥:进入对话或录入时暂停守护采集,LCD 显示"守护已暂停",退出后自动恢复。
- **录音 + 播放并发**(检测的同时播放提示音)是否支持全双工,须在实机基线阶段第一周内验证;若 media server 不支持,采用时分方案:播放提示音期间暂停采集,单次中断 ≤ 2 秒(方案细节见 PRD-04)。

## 识别通道

| 通道 | 覆盖声景 | 方案 |
|---|---|---|
| 环境声景分类 | `alarm_beep`、`water_flow`、`impact` | 多分类模型(int8 DS-CNN 优先) |
| 人声异常检测 | `distress_voice`(呻吟/痛苦叫声/哭喊/连续呼救) | 独立的人声异常检测模型 |
| 关键词/模板匹配 | `name_call_help`(与 PRD-02 共用模板库) | 本地关键词检测或 MFCC/声学嵌入模板匹配 |

## 输出接口

- `SoundObservation`:时间、声音类别、置信度、窗口长度。
- `DistressObservation`:人声事件类型、匹配的本地短语或人员标识、置信度、急促程度、重复次数;**不含**对话文本或原始音频。

识别层只输出类别与置信度,**不做告警决策**——是否提醒、升级、通知由状态机(PRD-03)决定。

## 性能与资源要求(实机验收)

- 单个 1 秒窗口端到端处理时间 < 500ms(Cortex-A7,不依赖 HiFi4 DSP)。
- 连续运行 2 小时无崩溃、无持续内存增长。
- 识别链路常驻内存(缓冲 + 特征 + 推理)初始预算 ≤ 8MB,以实机基线标定后修订。
- 模型体积预算见 PRD-07(闪存总增量 ≤ 2MB,受 16MB SPI NOR 主存储约束)。
- 记录单次推理耗时、CPU、内存占用数据,写入交付材料。

## 降级预案(阶段相对,不设日历日期)

- 板端量化推理示例接入 **2 个工作日**内跑不通 → 立即降级为 **MFCC + 小型 MLP/线性分类器**,权重导出为 C 数组,不新增重量级推理框架。
- 端侧识别阶段过半 CNN 仍不稳定 → 强制采用无第三方运行时的小型分类器,停止推理框架移植投入(见 PRD-07、PRD-08)。
